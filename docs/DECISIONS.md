# Decisions

- Implement one phase at a time and stop after Phase 0, as requested by the plan; canvas and domain behavior begin in Phase 1.
- Use Node 22 LTS in `.nvmrc` and CI while retaining the plan's Node >=20 / npm >=10 engine contract.
- Compile shared to CommonJS for NestJS; explicitly include the linked package in Vite dependency optimization and production CommonJS conversion so both apps consume `dist`.
- Install only dependencies used by the scaffold; canvas, state, queue, storage, and execution dependencies will be added in their corresponding phases.
- Add standard build/tooling dependencies (Nest CLI, TypeScript, ESLint tooling, React types, PostCSS, autoprefixer, ts-node, and ts-jest) to support the stack prescribed by the plan.
- Keep database schema synchronization and automatic migrations disabled. Phase 2 will introduce the first entity/migration; run migrations explicitly before starting deployments.
- Use a private MinIO bucket with bounded bootstrap retries. Public/signed asset access belongs to Phase 3.
- Bind infrastructure ports to localhost and provide development-only example credentials; production must supply its own credentials.
- The health endpoint indicates application readiness: Nest only starts listening after the database connects. Redis and storage readiness will be covered when those integrations are introduced.
- Run empty test suites successfully during scaffold; meaningful graph and orchestration tests are introduced with their phases.
- Do not remove assets on node deletion because undo may restore nodes; add orphan asset cleanup in future work.
- Use Rollup's official WASM distribution via an npm override: this Windows machine blocks the native `.node` module through Application Control, including outside the sandbox. This keeps Vite/Vitest portable without changing machine policy.
- Use Zod 4.6.7+ and Vitest 4.1.12+ after registry audit identified security fixes missing from older major versions; Vitest 4 retains the plan's Node 20 compatibility.
- Build local MinIO/MC containers from pinned official Go module revisions: Docker Hub repositories cannot be pulled and Quay returns 401 in this environment. Keep the existing S3 interface/Compose service names and persist data in the existing volume. Upstream community repositories are archived; reassess maintained storage before production.
- Make the database host port configurable with `POSTGRES_PORT`; this machine already has another PostgreSQL listener on 5432, so its uncommitted `.env` uses 5433 with a matching `DATABASE_URL`.
- Document `up -d` for the full stack: Compose `--wait` reports the successful one-shot `minio-init` exit as an error; use `--wait` only with the long-running services.
- Run FE and BE inside the default Compose stack at the user's request: use multi-stage Node 22 builds, a compiled NestJS runtime with production dependencies, and Nginx for the Vite bundle and API proxy. This enables the Docker Desktop group Start button after initial setup. Keep hot reload as an optional host workflow.
- Override host connection URLs with service-name URLs inside the API container; host port changes do not affect internal networking. Keep root `.env` out of Docker build context and supply runtime configuration through Compose.
- Use `unless-stopped` for long-running services so they recover during grouped startup; keep bucket bootstrap idempotent and one-shot. API startup depends on the bootstrap completing successfully.
- Phase 1 starts each session with two disconnected starter nodes (Text and Image Generator). Node numbering is derived from the current order within each type; graph IDs remain UUIDs.
- Keep Phase 1 entirely in browser memory. The Run controls explain that execution is coming; graph persistence and provider calls remain in their planned phases.
- Local uploads use UUID asset references in graph params and object URLs in a separate session store. Keep URLs until navigation so undo can restore replaced/deleted images; reject non-images and files larger than 20 MB locally.
- The generator's attach button creates an Image Upload node and its reference edge in one history transaction; it uses the same local file flow as standalone uploads.
- Track only graph nodes/edges in zundo (100 steps); keep viewport, selection, and drag previews outside history. Commit drag positions once on release. Use controlled React Flow node/edge change events for selection to avoid feedback loops from a selection observer.
- Keep native text-field shortcuts inside inputs; handle graph Delete/Backspace and Ctrl/Cmd undo shortcuts only outside editable fields. React Flow provides temporary Space panning.
- Add a separate strict shared test TypeScript configuration so test sources are checked but are not emitted into the shared runtime package.
- Phase 2 uses a fixed `CurrentUser` decorator and owner-scoped repository queries on all CRUD operations; foreign and missing records both return 404.
- Keep optimistic locking in one PostgreSQL UPDATE condition over ID, owner, and version. Increment version in SQL and read the result within the same transaction so another writer cannot change the returned document before it is captured. Bind graph JSON as a parameter cast to jsonb rather than interpolating it into SQL.
- Apply explicit TypeORM migrations before API startup in Docker and before the local Nest watcher. `synchronize` and TypeORM's automatic `migrationsRun` stay false; the single prototype API container owns startup migration execution.
- Limit Space names to 120 characters, request bodies to 2 MB, graphs to 1,000 nodes/5,000 edges, and versions to PostgreSQL integer range; reject unknown request/node-param fields on writes. Load-time repair preserves valid params, falls back per invalid field, drops unknown fields, and logs warnings.
- Use full document navigation for `/spaces/:id` and the list instead of adding a router dependency. The header back control flushes autosave first; native navigation uses `beforeunload` when dirty. Editor queries never refetch on window focus/reconnect, preventing silent replacement of local work.
- Autosave debounces for 800 ms, coalesces edits into a single serialized drain, and exposes `flush()`. Preserve dirty state after errors (including ambiguous network failures); 409 freezes writes until reload or copy. Save-as-copy is the recovery path for retaining conflicting local edits.
- Canonicalize JSON object keys when detecting changes: PostgreSQL jsonb reorders keys, which otherwise caused false autosaves immediately after load. This introduces the shared pure `stableStringify` helper ahead of Phase 5; no execution hashes or cache are implemented yet.
- Continue local-only image previews through Phase 2. Only UUID references enter persisted params; preview bytes/object URLs remain outside PostgreSQL. Phase 3 must upload/reselect these references before they can become durable assets.
- Keep schema migration as an explicit no-op for graph version 1 and reject unsupported versions clearly. Introduce persistence integration checks in CI now; defer the specified Playwright execution smoke test until Phase 5.

- Phase 3 executes one saved node at a time using a params snapshot. Edge input resolution remains Phase 4; generator references are empty and its own prompt is required. Text/upload executors are independently runnable. Force is accepted by the API but has no effect until caching arrives in Phase 5.
- Introduce BullMQ, the official AWS S3 SDK and Sharp for their planned queue/storage/image roles. Declare Express and Express/Multer types explicitly because the SSE and multipart controllers consume their interfaces. Install DejaVu fonts in the API image so Sharp renders prompt text consistently in mock PNGs.
- Normalize validated raster uploads/provider results to PNG; strip metadata, rotate uploads and decode at most 16,777,216 pixels. Support PNG/JPEG/WebP/AVIF/GIF (first frame); reject SVG and MIME spoofing. Hash the actual stored bytes. Store private objects under Space/asset UUIDs and stream through an ownership-checked API with nosniff. Delete a freshly written object if saving its metadata fails.
- Keep uploaded/generated assets when deleting nodes to preserve undo. Space deletion cascades database records but prototype object cleanup is deferred; add an orphan cleanup job before production. Integration scripts remove their own storage objects explicitly.
- Keep the BullMQ worker inside the single prototype API process; SSE uses per-Space in-memory subscriptions. Multiple API replicas require shared event fanout and coordinated migrations. PostgreSQL is the run source of truth: a partial active-run unique index deduplicates concurrent requests, and conditional queued/running updates prevent duplicate execution or late overwrites.
- Hash canonical node type/params with empty inputs for active-run idempotency now. Full effective-input hashing and succeeded-output caching remain Phase 5. A monotonically increasing database sequence prevents older asynchronous results/snapshots from replacing newer node state even when timestamps tie.
- Reconcile queued database rows every 5 seconds to repair Redis enqueue gaps. Mark running rows older than the configured recovery timeout failed with worker_lost. Producers fail quickly on Redis disconnect; workers reconnect. Executor deadlines abort providers and prevent late results from becoming successful runs.
- Run waits for pending uploads and serialized autosave before requesting execution. Keep run/upload progress outside graph history and autosave. Reconnect EventSource automatically, send 15-second heartbeat comments, and recover latest per-node runs on open and every 5 seconds. Node history requests return the newest 50 runs. Preserve the previous preview while a newer run is active.
- Save-as-copy clones referenced uploads into the destination Space, preserving ownership and durability if the original is deleted. Generated run history is not copied. Legacy session-only asset UUIDs require reselecting the image.
- Keep Nginx SSE buffering off and upload cap at 101 MB to allow the API's configurable 1–100 MB limit to return structured errors. The graph JSON cap stays 2 MB. Add Redis and local MinIO preparation to CI for real execution integration checks.

- Phase 4 resolves every connected input from the saved graph at request time and stores an immutable input snapshot with the queued run. Text values and uploaded assets resolve synchronously; generated image ports use all images from the latest succeeded run by sequence, scoped to Space/node. Newer failed/running runs do not hide older successful outputs. Reference order follows saved edge order, then output image order.
- A connected input with missing/empty output fails the run with its upstream display name before invoking a provider. Do not silently fall back from empty connected Text to a local prompt. Disconnected prompt falls back to its preserved local value; disconnected image references are optional and simply disappear. Snapshot domain errors become failed run events; database failures still propagate as infrastructure errors.
- Add a nullable run inputs column with a migration; old Phase 3 queued runs retain their original local-only behavior. Include resolved input values/assets in active-run identity now so changed connected inputs cannot deduplicate into an obsolete active run. Full cache hashing/caching/staleness remains Phase 5.
- Add the official AWS S3 request presigner. Sign private asset GETs for 900 seconds when execution begins, after validating Space ownership again. Persist asset IDs/content hashes, never expiring signed URLs. Compose signing uses its internal MinIO endpoint for the local provider; remote adapters need storage URLs reachable by their service.
- The mock actually downloads signed references and hashes their content into deterministic preview colors, rather than hashing expiring signatures. It remains a mock renderer, without visual image synthesis. Unit and integration checks verify input overrides, immutable snapshots, latest successful output selection, missing upstream errors and disconnect fallback.
- Show connected prompt/reference badges using the existing purple/green port colors. Connected Text appears read-only in the generator composer while its local prompt remains in graph params. Disconnect restores local editing; graph undo restores the connections and badges.

- Phase 5 persists batches with immutable graph/level snapshots and precreates all node run records. Waiting batch runs remain queued but unprepared; only prepared nodes reach BullMQ. The one-second coordinator advances a level after all its runs finish, prepares from this batch's successful outputs, and skips transitive failed/canceled dependencies while independent branches continue. Startup reconciliation resumes persisted progress.
- Allow one active batch per Space, enforced by a partial unique index and a transaction advisory lock. Concurrent Run all requests return the existing batch, including its original force setting. A batch waiting on an identical active single-node hash retries preparation after that run completes rather than violating the active-run index.
- Share a pure executionHash helper between API and FE: canonical type/params plus text values and image sha256 arrays sorted by port. Reference image order is meaningful; IDs and signed URLs are excluded from input values. Preserve full params including overridden local prompt fields. Invalid connected inputs add a diagnostic input value so they cannot deduplicate into valid active work with no references. Cache only succeeded runs in the same Space/node with the same hash, and validate referenced asset metadata. Force bypasses succeeded cache but retains active-run deduplication.
- Keep latest succeeded outputs separately from latest node state for input hash/stale calculations. Propagate upstream stale outputs to downstream nodes, including when a newer upstream run failed. Recover old outputs' image hashes through asset metadata; new outputs include sha256. Ignore older queued/waiting snapshots after input preparation and retain sequence/status protection for late results.
- Enforce per-Space running count under a PostgreSQL transaction advisory lock before claiming a prepared job. BullMQ worker concurrency supplies the global limit in the single API process. Capacity-blocked jobs remain queued in PostgreSQL and are re-enqueued by reconciliation. Global concurrency, SSE fanout, batch coordination and the default in-memory rate-limit storage assume one API replica; multi-instance deployment needs shared coordination/storage.
- Cancellation updates database status first, aborts all local controllers promptly, removes queued jobs and emits final states. Terminal status conditions prevent provider success or errors from replacing canceled results. Assets written immediately before an abort may be orphaned and follow the deferred cleanup policy. Canceling one batch node skips its descendants; canceling the batch cancels every unfinished node and preserves completed work.
- Add @nestjs/throttler for a shared 120-per-minute creation quota using the same fixed user as CurrentUser. Apply it only to node/batch run creation, keep cancellation unthrottled, and return Retry-After on 429. The quota spans handlers and IP addresses and resets when the prototype API restarts.
- Add @playwright/test as a web dev dependency and a Chromium UI smoke check for creating a Space, connecting Text, Run all, visible generated image, cache, stale and cancel. Existing starter nodes satisfy initial node creation. CI starts Vite against its running API and executes all integration scripts plus Playwright; local runs may reuse Docker's Nginx frontend. Bound API Jest to two workers; a synthetic reference test renders one image per request with a 15-second limit for native image/font initialization on a busy Windows host.

- Phase 6 moves node labels/category/description/keywords into shared registry metadata and derives the web catalog from it. Add category/description/keywords now as explicitly needed by the picker; defer the remaining Phase 7 platform changes. Keep only existing nodes and populated categories; icon presentation stays in the web app.
- Implement the picker with a native modal dialog and a combobox/listbox. Native inert background plus a Tab cycle keeps focus inside; opening focuses search and closing restores the Add node button, including after insertion. Block canvas shortcuts while open; ignore N inside editable elements, during IME composition and with Ctrl/Cmd/Alt. No dependency is needed.
- Rank normalized queries by label prefix, label substring, keyword, then category. Strip Unicode combining marks and map Vietnamese đ to d; preserve catalog order on ties and combine category chips with search. Alphabetize the registry-derived catalog by label for its default ordering. Keep descriptions as row tooltips and category as the visible subtitle.
- Keep existing viewport insertion coordinates and per-node offset, with one graph-store mutation per insertion so one Undo removes the node. The picker resets its search/category each time it opens. The edge-drop compatible picker is a separate Phase 6 stretch commit after the baseline acceptance checks.

- Phase 6 stretch handles an unfinished connection released specifically on the React Flow pane. Keep the flow-coordinate drop point and show the picker near the pointer, clamped inside the desktop viewport. Support both source-to-new-input and new-output-to-existing-target directions. Filter candidates through a pure shared helper that calls validateConnection, then revalidate against current graph state before atomically inserting the node and edge. Escape returns focus without inserting; N/plus resets compatibility filtering. Existing invalid-handle error notifications remain intact.

- Phase 7 derives NodeType and default graph/run schemas from registry keys; injectable schema factories, resolver and stale calculation support cloned registries in tests. Output port IDs follow their port types. Static Text/upload output and generated output share the same generic port resolver. UI components export presentation metadata discovered by Vite glob; executors are discovered from Nest providers. A new executor still needs ordinary Nest provider registration; resolver, hash, schemas and output code need no node-specific edits.
- Generalize run inputs to ordered per-port values and hash all text/media content hashes, excluding asset IDs/URLs. Resolve aliases and Auto to concrete model IDs before hashing/queueing, including batch preparation and legacy queued-run recovery. Migrate old prompt/reference snapshots; prior phase hashes intentionally miss cache once. Shared fixed vectors guard future hash changes.
- Keep the model catalog as versioned static rows with separate stable IDs, provider codes, external model IDs, capabilities/options and cost units. This row-shaped structure can move to a seeded database table later. Availability comes from registered runtime adapters and model status; defaults are resolved by ModelsService. Graph saves remain model-agnostic; execution checks capability/options and availability before invoking an adapter. Store canonical model/provider provenance on node_runs.
- Add available Mock Image Compact and a removed mock entry to exercise capability coercion, Advanced options and retired-model recovery. Image Studio is an illustrative unavailable custom-adapter entry, not a claim that a real vendor model is implemented. No key can enable it until an adapter is registered. Real adapters and billable calls remain deferred to Phase 11 cost guards. Mock LLM/TTS/video registrations expose catalog contracts only until their node/provider phases; they produce no media in Phase 7.
- Model changes coerce related params and reset descriptor-driven options through one graph mutation, so Undo restores the previous model/settings atomically. Default changes do not silently rewrite graph params: Auto outputs become stale and unsupported settings fail readably at run time. FE refreshes availability/defaults periodically and on reload.
- Extend asset metadata to image/video/audio, bigint bytes, nullable dimensions and duration. Images retain Sharp normalization. Provider audio/video bytes or Readable streams use per-kind bounds, MIME allowlists and magic-byte signatures; these checks identify container signatures, not complete codec/duration validity. Provider dimensions/duration remain trusted metadata until the media-specific phases. Streams are bounded and buffered in Phase 7; multipart streaming and HTTP Range remain Phase 10. User upload stays image-only.
- Retry only typed transient pre-acceptance provider errors or network failures, with bounded exponential jitter and Retry-After. An accepted-task callback or error taskId forbids retries. Timeout, cancellation, quota, content and invalid-request failures do not automatically retry. Preserve typed user messages and log only provider/error classification for unknown errors, avoiding raw payloads and signed URLs. This intentionally favors redaction over diagnostic payload retention.
- Enforce provider-wide and kind-wide running counts under PostgreSQL transaction advisory locks in addition to per-Space counts. Blocked jobs stay queued for reconciliation. The worker, batch coordinator, event fanout and throttling retain the single-API prototype deployment assumption. Provider limits default to two and can be configured per uppercase code.
- Existing integration assertions remain in place; fixture shapes and input snapshot assertions were updated from prompt/references to ports. Phase 7 adds fake-registry, fixed-hash, model/default/availability, coercion, provider retry/limits, media storage and browser recovery checks. No dependencies were added.

- Phase 8 adds Assistant as a registry entry, discovered UI component and Nest-registered executor; the generic port resolver and output/run schemas required no node-specific edits. A generic optional registry executionVersion participates in executionHash only when defined; Assistant supplies ASSISTANT_PRESETS_VERSION. Changing preset text requires a version bump; existing image hash vectors stay unchanged. FE stale calculation also passes its registry to this shared helper.
- Join connected context values in edge order, followed by a nonempty local message, using two newlines. Count separators toward the 20,000-character limit; reject excess context without truncation. Accept image-only instructions, reject a wholly empty request, use maxTokens=6000, cap completed output at 20,000 characters, and reject empty provider output. The local message is capped at 8,000 characters by both schema and UI. Lengths follow JavaScript UTF-16 string.length, consistent with textarea maxlength.
- Implement nonstreaming LlmProvider.complete with system/messages/model/maxTokens and optional usage metadata. Reuse provider registry, typed retry/redaction, cancellation, timeouts and Space/provider/kind capacity limits. No token delta events in v1; SSE can carry run.delta later. Usage accounting remains Phase 11. Cache repeated LLM inputs intentionally; Force rerun invokes the provider again even though the deterministic mock returns the same text.
- Replace the mock LLM metadata stub with a working deterministic, preset-aware provider with a 1.2-second abortable delay and MOCK_FAILURE_RATE injection. Mock vision fetches private signed references and echoes ordered content fingerprints, not transient URLs or visual-analysis claims. Add a text-only mock model to verify nonvision rejection and an unavailable custom LLM catalog example for the disabled model menu. TTS/video remain metadata stubs until Phases 9–10; no billable provider calls or new dependencies.
- Assistant results render as plain text with bounded scroll, read-only selection and a clipboard Copy button. A denied clipboard operation offers manual copying. Model selection uses the kind-filtered models endpoint; stale computation retains the full catalog. The existing image composer now displays a connected Assistant's successful text rather than the overridden local prompt. Picker search/count/order expectations change to include the new Text category entry.

- Browser acceptance found that reloading after a canceled run populated successful-history metadata but omitted the previous output from the display store. Restore successful outputs generically during history recovery, retain the latest successful sequence and reject a late success for the same canceled run. Add regression coverage for text recovery and stale replacements; this also fixes the existing image preview recovery path. Clipboard assertions normalize Windows CRLF while preserving the copied content.

- Phase 9 adds Voiceover as one shared registry entry, one discovered UI component and one Nest-registered executor. Generic input resolution, output schemas, hash/cache and stale propagation require no voiceover branches. Model selection uses GET /models?kind=tts; voice/language and speed bounds derive from the selected model. The connected script overrides local text, disables editing, and disconnect restores it. Retain optional options for the generic model-controls/coercion contract even though mock TTS has no extra descriptors.
- Enforce a 5,000-character limit on both local and effective connected scripts; reject oversized connected Assistant output without truncation. Empty connected input fails rather than falling back. Keep save validation model-agnostic and runtime capability validation before calling TTS. Speed uses 0.05 steps in the superset 0.75–1.5 range; mock catalog ranges align with that step. JavaScript UTF-16 lengths match textarea maxlength.
- Replace the mock TTS metadata stub with TtsProvider.synthesize and an abortable deterministic mock. Generate a 16 kHz mono 16-bit PCM WAV entirely in Node. Duration is whitespace word count / 2.5 / speed, rounded to milliseconds, bounded to 0.2–300 seconds; the upper limit fits below the default 25 MB audio cap (9,600,044 bytes). Write proper RIFF/fmt/data sizes, apply soft tone envelopes and derive tones from script/voice/language/model. This exercises audio flow, not speech synthesis or language pronunciation. Yield between one-second sample blocks so cancellation and other requests can run; cache Math functions outside the sample loop for predictable synthesis cost.
- Store provider audio via the existing MIME-sniffed AssetsService path with duration and nullable dimensions, return audio AssetRefs, and use the existing authenticated asset endpoint with audio/wav and .wav Content-Disposition. Native WAV playback works with full-body responses in Phase 9. Range/multipart streaming remains Phase 10; real TTS adapters remain Phase 11 cost guards. Show the mock-tone limitation beside the player. No added dependencies, migrations or environment settings.
- Add Mock Narrator with distinct voice/language/speed capabilities to exercise atomic model coercion and Undo, and an unavailable Voice Studio custom-adapter example for menu availability. The mock provider retains MOCK_FAILURE_RATE and the shared typed retry, timeout, provider/kind/Space limits and cancellation guards. Add API/browser checks for script-writer dataflow, actual WAV playback, media headers, local fallback, cache, force and cancellation. Picker category/order expectations now include Audio/Voiceover.
