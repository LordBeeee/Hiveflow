# Decisions

- Implement one phase at a time and stop after Phase 0, as requested by the plan; canvas and domain behavior begin in Phase 1.
- Use Node 22 LTS in `.nvmrc` and CI while retaining the plan's Node >=20 / npm >=10 engine contract.
- Compile shared to CommonJS for NestJS; explicitly include the linked package in Vite dependency optimization and production CommonJS conversion so both apps consume `dist`.
- Install only dependencies used by the scaffold; canvas, state, queue, storage, and execution dependencies will be added in their corresponding phases.
- Add standard build/tooling dependencies (Nest CLI, TypeScript, ESLint tooling, React types, PostCSS, autoprefixer, ts-node, and ts-jest) to support the stack prescribed by the plan.
- Keep database schema synchronization and automatic migrations disabled. Phase 2 will introduce the first entity/migration; run migrations explicitly before starting deployments.
- Use a private MinIO bucket with bounded bootstrap retries. Public/signed asset access belongs to Phase 3.
- Bind infrastructure ports to localhost and provide development-only example credentials; production must supply its own credentials.
- The health endpoint indicates application readiness: Nest only starts listening after the database connects. Redis and storage readiness will be covered when those integrations are introduced.
- Run empty test suites successfully during scaffold; meaningful graph and orchestration tests are introduced with their phases.
- Do not remove assets on node deletion because undo may restore nodes; add orphan asset cleanup in future work.
- Use Rollup's official WASM distribution via an npm override: this Windows machine blocks the native `.node` module through Application Control, including outside the sandbox. This keeps Vite/Vitest portable without changing machine policy.
- Use Zod 4.6.7+ and Vitest 4.1.12+ after registry audit identified security fixes missing from older major versions; Vitest 4 retains the plan's Node 20 compatibility.
- Build local MinIO/MC containers from pinned official Go module revisions: Docker Hub repositories cannot be pulled and Quay returns 401 in this environment. Keep the existing S3 interface/Compose service names and persist data in the existing volume. Upstream community repositories are archived; reassess maintained storage before production.
- Make the database host port configurable with `POSTGRES_PORT`; this machine already has another PostgreSQL listener on 5432, so its uncommitted `.env` uses 5433 with a matching `DATABASE_URL`.
- Document `up -d` for the full stack: Compose `--wait` reports the successful one-shot `minio-init` exit as an error; use `--wait` only with the long-running services.
- Run FE and BE inside the default Compose stack at the user's request: use multi-stage Node 22 builds, a compiled NestJS runtime with production dependencies, and Nginx for the Vite bundle and API proxy. This enables the Docker Desktop group Start button after initial setup. Keep hot reload as an optional host workflow.
- Override host connection URLs with service-name URLs inside the API container; host port changes do not affect internal networking. Keep root `.env` out of Docker build context and supply runtime configuration through Compose.
- Use `unless-stopped` for long-running services so they recover during grouped startup; keep bucket bootstrap idempotent and one-shot. API startup depends on the bootstrap completing successfully.
- Phase 1 starts each session with two disconnected starter nodes (Text and Image Generator). Node numbering is derived from the current order within each type; graph IDs remain UUIDs.
- Keep Phase 1 entirely in browser memory. The Run controls explain that execution is coming; graph persistence and provider calls remain in their planned phases.
- Local uploads use UUID asset references in graph params and object URLs in a separate session store. Keep URLs until navigation so undo can restore replaced/deleted images; reject non-images and files larger than 20 MB locally.
- The generator's attach button creates an Image Upload node and its reference edge in one history transaction; it uses the same local file flow as standalone uploads.
- Track only graph nodes/edges in zundo (100 steps); keep viewport, selection, and drag previews outside history. Commit drag positions once on release. Use controlled React Flow node/edge change events for selection to avoid feedback loops from a selection observer.
- Keep native text-field shortcuts inside inputs; handle graph Delete/Backspace and Ctrl/Cmd undo shortcuts only outside editable fields. React Flow provides temporary Space panning.
- Add a separate strict shared test TypeScript configuration so test sources are checked but are not emitted into the shared runtime package.
- Phase 2 uses a fixed `CurrentUser` decorator and owner-scoped repository queries on all CRUD operations; foreign and missing records both return 404.
- Keep optimistic locking in one PostgreSQL UPDATE condition over ID, owner, and version. Increment version in SQL and read the result within the same transaction so another writer cannot change the returned document before it is captured. Bind graph JSON as a parameter cast to jsonb rather than interpolating it into SQL.
- Apply explicit TypeORM migrations before API startup in Docker and before the local Nest watcher. `synchronize` and TypeORM's automatic `migrationsRun` stay false; the single prototype API container owns startup migration execution.
- Limit Space names to 120 characters, request bodies to 2 MB, graphs to 1,000 nodes/5,000 edges, and versions to PostgreSQL integer range; reject unknown request/node-param fields on writes. Load-time repair preserves valid params, falls back per invalid field, drops unknown fields, and logs warnings.
- Use full document navigation for `/spaces/:id` and the list instead of adding a router dependency. The header back control flushes autosave first; native navigation uses `beforeunload` when dirty. Editor queries never refetch on window focus/reconnect, preventing silent replacement of local work.
- Autosave debounces for 800 ms, coalesces edits into a single serialized drain, and exposes `flush()`. Preserve dirty state after errors (including ambiguous network failures); 409 freezes writes until reload or copy. Save-as-copy is the recovery path for retaining conflicting local edits.
- Canonicalize JSON object keys when detecting changes: PostgreSQL jsonb reorders keys, which otherwise caused false autosaves immediately after load. This introduces the shared pure `stableStringify` helper ahead of Phase 5; no execution hashes or cache are implemented yet.
- Continue local-only image previews through Phase 2. Only UUID references enter persisted params; preview bytes/object URLs remain outside PostgreSQL. Phase 3 must upload/reselect these references before they can become durable assets.
- Keep schema migration as an explicit no-op for graph version 1 and reject unsupported versions clearly. Introduce persistence integration checks in CI now; defer the specified Playwright execution smoke test until Phase 5.

- Phase 3 executes one saved node at a time using a params snapshot. Edge input resolution remains Phase 4; generator references are empty and its own prompt is required. Text/upload executors are independently runnable. Force is accepted by the API but has no effect until caching arrives in Phase 5.
- Introduce BullMQ, the official AWS S3 SDK and Sharp for their planned queue/storage/image roles. Declare Express and Express/Multer types explicitly because the SSE and multipart controllers consume their interfaces. Install DejaVu fonts in the API image so Sharp renders prompt text consistently in mock PNGs.
- Normalize validated raster uploads/provider results to PNG; strip metadata, rotate uploads and decode at most 16,777,216 pixels. Support PNG/JPEG/WebP/AVIF/GIF (first frame); reject SVG and MIME spoofing. Hash the actual stored bytes. Store private objects under Space/asset UUIDs and stream through an ownership-checked API with nosniff. Delete a freshly written object if saving its metadata fails.
- Keep uploaded/generated assets when deleting nodes to preserve undo. Space deletion cascades database records but prototype object cleanup is deferred; add an orphan cleanup job before production. Integration scripts remove their own storage objects explicitly.
- Keep the BullMQ worker inside the single prototype API process; SSE uses per-Space in-memory subscriptions. Multiple API replicas require shared event fanout and coordinated migrations. PostgreSQL is the run source of truth: a partial active-run unique index deduplicates concurrent requests, and conditional queued/running updates prevent duplicate execution or late overwrites.
- Hash canonical node type/params with empty inputs for active-run idempotency now. Full effective-input hashing and succeeded-output caching remain Phase 5. A monotonically increasing database sequence prevents older asynchronous results/snapshots from replacing newer node state even when timestamps tie.
- Reconcile queued database rows every 5 seconds to repair Redis enqueue gaps. Mark running rows older than the configured recovery timeout failed with worker_lost. Producers fail quickly on Redis disconnect; workers reconnect. Executor deadlines abort providers and prevent late results from becoming successful runs.
- Run waits for pending uploads and serialized autosave before requesting execution. Keep run/upload progress outside graph history and autosave. Reconnect EventSource automatically, send 15-second heartbeat comments, and recover latest per-node runs on open and every 5 seconds. Node history requests return the newest 50 runs. Preserve the previous preview while a newer run is active.
- Save-as-copy clones referenced uploads into the destination Space, preserving ownership and durability if the original is deleted. Generated run history is not copied. Legacy session-only asset UUIDs require reselecting the image.
- Keep Nginx SSE buffering off and upload cap at 101 MB to allow the API's configurable 1–100 MB limit to return structured errors. The graph JSON cap stays 2 MB. Add Redis and local MinIO preparation to CI for real execution integration checks.

- Phase 4 resolves every connected input from the saved graph at request time and stores an immutable input snapshot with the queued run. Text values and uploaded assets resolve synchronously; generated image ports use all images from the latest succeeded run by sequence, scoped to Space/node. Newer failed/running runs do not hide older successful outputs. Reference order follows saved edge order, then output image order.
- A connected input with missing/empty output fails the run with its upstream display name before invoking a provider. Do not silently fall back from empty connected Text to a local prompt. Disconnected prompt falls back to its preserved local value; disconnected image references are optional and simply disappear. Snapshot domain errors become failed run events; database failures still propagate as infrastructure errors.
- Add a nullable run inputs column with a migration; old Phase 3 queued runs retain their original local-only behavior. Include resolved input values/assets in active-run identity now so changed connected inputs cannot deduplicate into an obsolete active run. Full cache hashing/caching/staleness remains Phase 5.
- Add the official AWS S3 request presigner. Sign private asset GETs for 900 seconds when execution begins, after validating Space ownership again. Persist asset IDs/content hashes, never expiring signed URLs. Compose signing uses its internal MinIO endpoint for the local provider; remote adapters need storage URLs reachable by their service.
- The mock actually downloads signed references and hashes their content into deterministic preview colors, rather than hashing expiring signatures. It remains a mock renderer, without visual image synthesis. Unit and integration checks verify input overrides, immutable snapshots, latest successful output selection, missing upstream errors and disconnect fallback.
- Show connected prompt/reference badges using the existing purple/green port colors. Connected Text appears read-only in the generator composer while its local prompt remains in graph params. Disconnect restores local editing; graph undo restores the connections and badges.
